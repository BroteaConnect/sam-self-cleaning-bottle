# Internationalization

English is the source language (`defaultLocale: "en"`); Spanish is a full
mirror. Both are `required`, so both must be complete for CI to pass.
Configuration lives in `src/locales/config.json`.

## Dictionaries

`src/locales/en.json` and `src/locales/es.json` are flat JSON objects
with alphabetically sorted keys. Every user-facing string on the page
resolves through `t(locale, key)` from `src/lib/i18n` — there is no
hardcoded copy in components or pages.

Key groups:

- `hero.title` / `hero.tagline` / `hero.sub` / `hero.cta`
- `features.title`, `features.1-4.title` / `features.1-4.body`
- `how.title`, `how.step1-3`
- `faq.title`, `faq.1-4.q` / `faq.1-4.a`
- `cta.title` / `cta.sub`
- `meta.description`
- `form.*` (lead form labels and status messages), `nav.language`

## The CI gate

`src/locales/locales.test.mjs` runs with `npm test` and blocks the merge
if, for any required locale:

- a key from the default locale is missing, extra, or empty
- keys are not alphabetically sorted
- `{placeholder}` names differ from the English source
- a plural key is missing the forms the language needs (`.other`, and
  `.one` where applicable)

The test file is generated by the factory — never edit it in this repo.

## Adding or changing copy

1. Add/edit the key in `en.json` (keep the file sorted).
2. Mirror the same key in `es.json` with the Spanish translation.
3. Reference it in the page: `{t(locale, 'my.key')}`.
4. `npm test` locally; CI runs the same gate.

## Adding a language

Run `brotea i18n add <code>` from the factory. Until the new locale is
added to `required`, `t()` falls back to English and the incomplete
dictionary does not block deploys.
